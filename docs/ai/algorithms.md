# AIの仕組みと判断仕様

麻雀スズメのAIは、自分の手牌と公開情報から合法手を比較し、対局相手や判断方式の比較実験に使えます。
現在のRandom・Greedy・Ukeireは、人が定めた比較規則と限定的な先読みを実装したものです。
対局データで学習したモデルや重みは使用していません。
実装は[AIの呼出し口](../../src/ai.rs)、[設定](../../src/ai/config.rs)、[判断処理](../../src/ai/search.rs)に分かれています。

## 三つの判断方式

全方式で、合法な和了があれば和了を選びます。和了がなければ次局への進行を優先し、
操作が一つだけならその操作を選びます。それ以外の場面で、次の比較を行います。

| 設定名 | 操作の選び方 | 主な制限 |
|---|---|---|
| `random` | 受け取った合法手の一覧から均等に選ぶ | 牌効率を評価しない。同じ牌の別添字、打牌とリーチは別の選択肢として数える |
| `greedy` | リーチ、向聴数を改善する鳴き、打牌の順に検討する | 有効牌の未公開枚数を比較せず、残り0枚の待ちを選ぶ場合がある |
| `ukeire` | 向聴数、有効牌数、牌の形、ドラ、危険度を評価し、設定に応じて次のツモを先読みする | 相手の手牌推定、正確な和了確率、期待得点は求めない |

操作の合法性は対局処理が決めます。AIは[公開観測と合法手](../../src/game.rs)を受け取り、
選んだ操作を返します。合法手は `Game::legal_actions` から取得し、適用は `Game::apply` で行います。

## 設定と再現性

プリセットは判断方式と計算量をまとめた設定です。名前による勝率の順位は保証しません。

| プリセット | 方式 | `max_evaluations` | `lookahead_depth` | `risk_weight` |
|---|---|---:|---:|---:|
| `beginner` | random | 0 | 0 | 0 |
| `standard` | greedy | 1024 | 0 | 1 |
| `strong` | ukeire | 8192 | 2 | 4 |

`AiConfig::default()` は `standard`、AI用の乱数種は0です。
TOML・JSONでは、`preset` と `algorithm` のどちらかを選び、予算・深さ・防御重みを個別に上書きできます。
両方の同時指定は拒否します。方式だけを指定した場合、randomはbeginner、greedyはstandard、ukeireはstrongの値を基にします。
設定の解決と組合せの検査は[共通設定の実装](../../crates/suzume-api/src/config.rs)で行います。

| 項目 | 受け付ける値 |
|---|---|
| `max_evaluations` | 0〜100,000。Randomは0、GreedyとUkeireは1以上 |
| `lookahead_depth` | RandomとGreedyは0、Ukeireは1または2 |
| `risk_weight` | 0〜1000。Randomは0 |
| `seed` | Rustでは `u64`。TOML・JSONでは `"0"`〜`"18446744073709551615"` の正規形の十進文字列 |

AI用の乱数種と配牌の乱数種は別です。同じ実装・観測・合法手一覧・実効設定なら同じ判断を返します。
乱数はAI用の種と公開観測から生成し、現在時刻、OS乱数、真の山順序、配牌の種を参照しません。
設定ファイルの例と起動方法は[CLIの設定手順](cli.md)、全項目の意味は[共通設定仕様](../api/configuration.md)を参照してください。

## 入力の検査と情報の範囲

AIが受け取るのは、自分の手牌、全員の捨て牌と副露、得点、リーチ状態、ドラ表示牌などの公開観測と合法手です。
他家の手牌や真の山順序は渡しません。
[入力検査](../../src/ai/validation.rs)では、席、手牌番号、副露、構造枚数、公開河、同じ牌が4枚以内であることなどを確認します。
不正な設定・観測・操作や空の合法手一覧は `AiError` として返します。
組込みAIを `Policy::choose_action` から呼ぶ場合、これらの失敗は `None` になります。

この入力検査だけでは、役、振聴、応答中の手番を含む最終的な合法性は判定できません。
外部から独自に作った操作をそのまま採用せず、対局処理が返した合法手を使ってください。

## 公開情報から数える

各牌の既知枚数は、自分の手牌、全員の副露、鳴かれていない河、ドラ表示牌の合計です。
鳴かれた牌は副露に含まれるため、河と二重に数えません。
自分の副露も `Observation.melds` と公開プレイヤー情報の両方で数えず、両者の一致を入口で検査します。

未公開枚数は `4 - 既知枚数` です。他家の手牌、伏せた王牌、未表示のドラ表示牌も含むため、
実際に山に残っている枚数とは異なります。先読みでは、この集合のどの牌も未公開枚数に比例して次のツモになり得ると仮定します。
相手の打牌選択から手牌を推定する処理はありません。
外部の判断方式も `unseen_tile_counts` で同じ入力検査と計数を利用できます。

## 向聴数と有効牌

向聴数は和了形までの距離を表し、0はテンパイ、-1は和了形です。
通常形・七対子・国士を比較し、副露がある場合は通常形を扱います。
副露と手牌で同じ牌を4枚所有しているとき、その5枚目を必要とする待ちはテンパイに数えません。
他家の河などに待ち牌が全て見えている場合は、テンパイでも有効牌0枚になり得ます。

有効牌数は、打牌後の手牌へ候補牌を1枚加え、向聴数が下がる牌の未公開枚数を足した値です。
役のある和了確率や打点を直接計算した値ではありません。
計算には[向聴数と待ちの実装](../../src/hand.rs)を使います。

## GreedyとUkeireの比較基準

Greedyは、評価できたリーチ候補を優先します。次に、鳴かない場合より向聴数が下がる鳴きを検討し、
槓は向聴数が同じ場合も候補にします。鳴く条件は、暗槓、役牌が成立する場合、または断么九を見込める場合です。
チー・ポンの後は打牌まで比較し、食い替えになる牌を除きます。

通常の打牌は、向聴数、危険度と防御重みの積、残る牌のつながり、捨てる牌のIDの順で比較します。
防御は向聴数が等しい場合に使い、重み0で無効になります。正の重み同士では危険度の順位は変わりません。

Ukeireの深さ1では、有効牌が残るリーチ候補があればそれらを優先し、次の整数値が高い候補を選びます。
鳴きにはGreedyと同じ条件を使います。

`-2000 × 向聴数 + 10 × 有効牌数 + 牌のつながり + 15 × 保持ドラ数 - 20 × risk_weight × danger`

この値は候補を比較するための指標で、期待得点ではありません。
Ukeireでは防御項を他の評価項から差し引くため、防御重みの大きさも判断へ反映されます。

牌のつながりは、同種2枚に6、3枚に12、4枚に9を加点し、同じ色の隣り合う牌種に4、
一つ飛びの牌種に2を加えます。ドラは公開済みの表示牌ごとに、手牌と副露に持つ枚数を数えます。
計算式は判断処理の `shape_value`、`dora_value`、`static_value` に対応します。

`danger` はリーチしている各他家について計算します。候補牌がその人の河にあれば0、
なければ字牌1・一九牌2・中張牌3を加算します。
筋、壁、相手の待ち推定、副露による攻撃への対応は含まず、放銃確率や安全性を表す値ではありません。

## 深さ2の範囲

Ukeireで深さ2を指定すると、打牌候補に仮のツモを加え、次の打牌まで比較します。

1. 深さ1の上位から、打牌後の手牌が異なる候補を最大3つ選びます。同じ手牌になる打牌とリーチは一つにまとめます。
2. 各候補で同じ乱数系列を使い、未公開枚数に比例して次のツモを4回選びます。
3. 仮のツモ後に和了形となれば、その標本の比較を終えます。それ以外では、向聴数・防御・つながりによる次の打牌の上位2候補を残します。
4. 各打牌後の有効牌を計算し、深さ1の式で標本内の最良値を選びます。仮に引いた牌は、その枝の未公開枚数から1枚減らします。
5. 4標本を完了した平均値から、最初の打牌の危険度に `20 × risk_weight` を掛けた値を引いて比較します。同点では深さ1の評価値、合法手一覧の順を使います。

リーチ後の枝はツモ切りに限定します。仮のツモで和了形となった標本の値は、
`2000 + 15 × 仮ツモ前の保持ドラ数` です。役の有無や支払点数を再計算する処理ではありません。

この先読みは、最初の打牌、仮のツモ、次の打牌、その先の有効牌という範囲に限られます。
他家の行動は進めず、少数の標本から候補を比較します。全ての山を展開する探索や、UCTを使うモンテカルロ木探索は実装していません。

## 計算予算の単位

全ての打牌・鳴きの候補と先読みが、1回の判断の中で同じ予算を使います。
`evaluations` は `hand::shanten` を実際に呼び出した回数です。
手牌の牌数配列、副露に含まれる各牌の枚数、副露数が同じ計算結果は再利用し、予算に加算しません。
公開牌の計数、牌の形の確認、整数の比較にかかる処理は、この回数に含めません。
候補数、手牌長、副露数、公開河の長さは入力検査で別に制限します。

予算不足で得られなかった数値は `None` にします。有効牌数を最後まで計算できなかった場合はGreedyの基準へ戻り、
未計算の有効牌を0枚として比較しません。深さ2で比較対象のいずれかを完了できなければ、
完了した候補だけを有利に扱わず、深さ1の比較結果を使います。

`budget_exhausted` は、追加の向聴計算を要求した時点で予算が尽きていたことを示します。
予算ちょうどで判断が完了した場合には、この理由だけでtrueにはなりません。
予算は実行時間やメモリ使用量の上限ではなく、判断内部には時間制限を置いていません。

## 判断結果を読む

`ConfiguredAi::new` は設定を検査し、`decide` は選んだ操作と根拠を `Decision` として返します。
従来の `GreedyAi` は `standard`、AI用の種0で同じ判断処理を呼びます。

| フィールド | 意味 |
|---|---|
| `config` | プリセットや上書き指定を解決し、検査した実効設定 |
| `action` / `reason` | 選んだ操作と理由。理由は `win`、`forced`、`random`、`greedy`、`ukeire`、`lookahead`、`budget_fallback` |
| `candidates` | 受け取った合法手と同じ順序の候補。未計算の数値は `None` |
| 候補の `shanten` | 候補を進めた後の向聴数 |
| 候補の `ukeire` | 向聴数を下げる牌の未公開枚数の合計 |
| 候補の `danger` | 他家のリーチと河から計算する危険度 |
| 候補の `lookahead_value` | 完了した深さ2の4標本の平均値。最初の打牌の危険度を差し引く前の値 |
| `candidates_evaluated` | 向聴数まで求めた候補数 |
| `evaluations` | 再利用を除いた向聴計算の呼出し回数 |
| `budget_exhausted` | 追加計算を必要とした時点で予算が尽きたか |

和了・次局・唯一の操作は探索せず選ぶため、向聴計算は0回です。Randomも向聴計算を行いません。
理由名だけで評価の完了範囲を決めず、候補の未計算値と計数を併せて確認してください。

`Decision` 自体は局面IDを発行しません。APIとログで、観測、セッションID、更新番号、操作列に対応付けます。
判断結果には手牌を推測できる値が含まれるため、他家の判断記録を通常の共有用ログへそのまま載せません。
AI判断の保存には、[CLIの記録設定](cli.md#記録形式と終了理由)で旧 `replay` 形式を指定します。

## 評価結果とAIの追加

既存の[固定対照評価](evaluation.md)では、他の3席を同じGreedy設定にして、UkeireとRandomを各32東風戦で比較しました。
全64試合の成否・成績は[評価結果](results.md)にあります。この比較だけでは、UkeireがGreedyより強いことや、人間相手の強さは判断できません。

新しい判断方式は `Policy` として追加でき、同じ観測と合法手を利用できます。
外部APIの設定名へ追加する場合は、設定型・生成Schema・SDK・ログとの対応も更新します。
木探索と学習器の接続、観測と189個の行動番号の対応は[AIの追加手順](extension.md)と[研究用環境](../api/environment.md)を参照してください。
