# 木探索・強化学習から使用する対局環境

この環境は1回の `step` で1席の1操作を進める、多人数の逐次手番型です。4人が同時に1手ずつ打つ形式ではありません。鳴き・ロンへの応答と局終了後の進行も、それぞれ操作として数えます。使用例は [SDK](../../packages/suzume/README.md)、記録から遷移を作る方法は [ログ仕様](../logging/README.md)にあります。

## 操作

`environment_reset` は `seed` と `max_steps`（1〜10000、省略10000）を受け取り、新規環境を作ります。`environment_view` は状態を変えず現在の観測を返します。`environment_step` は `session_id`、`expected_revision`、`action_id` を受け取ります。通常の対局モードと環境モードは1つのEngine内で排他的です。

Rustでは `Environment::new`、`state`、`step`、`fork` を利用できます。`fork` は山・手牌・履歴まで複製する、信頼する実験コード用の分岐です。大規模探索向けの低費用な永続状態を保証するものではありません。通常の `Policy` や外部行動選択器へ、この全情報状態を渡さないでください。不完全情報木探索では、公開観測から自分で仮説局面を構成する責務を探索側に持たせます。

## 観測

`EncodedObservation` は次の内容です。

| 項目 | 定義 |
|---|---|
| `schema_version` | 観測形式の版。現在1 |
| `actor` | 次に操作する席 |
| `view` | actorの自身の手牌と公開情報だけを含むGameView |
| `hand_counts` | 牌種0〜33順の手牌枚数、長さ34 |
| `visible_counts` | 自身の手牌＋全副露＋鳴かれていない捨て牌＋ドラ表示牌、長さ34 |
| `legal_mask` | 行動ID0〜188順の真偽、長さ189 |

鳴かれた捨て牌は副露と重複するため再加算しません。`4 - visible_counts[t]` は見えていない同種牌の枚数であり、山に残る枚数ではありません。他家の手牌や王牌も含みます。過去に観測した情報を保持する再帰モデルや、複数巡の特徴を作る処理は利用側で追加できます。

## 行動空間：189要素

`t` は牌種0〜33、`s` は順子の最小牌種、`p` は鳴いた牌の順子内位置0〜2です。

| ID | 行動 | 条件 |
|---|---|---|
| 0〜33 | `discard(t)` | 手牌の同種牌のうち最初の合法な位置へ解決 |
| 34〜67 | `riichi(t)` | ID = 34 + t。同じ正規化を使用 |
| 68 | ツモ和了 | 合法手に存在するとき |
| 69 | ロン | 合法手に存在するとき |
| 70 | ポン | 合法手に存在するとき |
| 71 | 明槓 | 合法手に存在するとき |
| 72 | 見送り | 合法手に存在するとき |
| 73 | 次局・終局への進行 | 合法手に存在するとき |
| 74〜107 | 暗槓 | ID = 74 + t |
| 108〜188 | チー | ID = 108 + 3s + p。sは数牌で各色の1〜7のみ |

チー領域の129〜134、156〜161、183〜188は、順子が各色の8・9から始まることになるため予約番号です。常にmaskがfalseです。実際に利用可能なチー形は63種類ですが、各色9種類を基準に番号を置くことで牌種との算術的な対応を維持します。

行動番号の型の範囲内にあることと、その局面で合法であることは異なります。必ず現在のmaskを使用します。IDを選択すると合法手リストの最初の対応操作へ戻します。物理的な手牌位置まで戻す一対一対応ではありません。正確な操作の再生には別途 `WireAction` を記録します。

## 報酬と終了

返される `EnvironmentTransition.actor` は今回操作した席、`observation.actor` は次に操作する席です。同じ席とは限りません。初期状態や読み取りだけの `state` は操作・actorがnullで、報酬は全席0です。

報酬は席ごとに `操作後の点数 - 操作前の点数`、単位は点です。順位報酬、シャンテン改善報酬、割引率は組み込みません。リーチ供託の移動は `escrow_delta = 操作後の供託点 - 操作前の供託点` に分けるため、`sum(rewards) + escrow_delta = 0` です。学習側が供託をどの席へ割り当てるかは、別の報酬設計として明示して実装してください。

`terminated` は東風戦が規則どおり終了した場合だけtrueです。`truncated` は未終了のまま操作上限へ達した場合だけtrueで、両者は同時にtrueになりません。終了または打切り時の通常の `observation` はnullです。打切りの場合だけ、最後の次手番の観測を `final_observation` に残します。時間制限で試行を止めても、本来継続する局面の価値推定を学習器が利用できるようにするためです。自然終局と通常継続時の `final_observation` はnullです。再度stepを呼ぶと状態を変えず `step_limit` を返します。ログ由来のデータでは外部中断もtruncatedとなり、同じ最終観測を保持します。

この版に学習済みの強化学習モデルやMCTS/UCT本体は含みません。組込みUkeireの限定探索と、外部から合法IDを選ぶ入口を提供します。算法の差替えと測定条件は [AI拡張](../ai/extension.md)に定めます。
