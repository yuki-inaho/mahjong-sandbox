## 原文保持・検査境界の確認

### 保存する文字列と解析用の値

JSONパーサは指定されたJSONポインタ `/event` と `/annotations` の開始・終了位置だけを記録します。オブジェクトのキーは復号後に重複を検査し、ポインタ内の `~` と `/` をエスケープします。外側の `event` キーがUnicodeエスケープで書かれた場合や、注釈の内側に同名のキーがある場合も、正しい部分文字列を取得できることを確認しました。

イベントは取得した原文から既存のイベントパーサへ渡します。解析済みの `Number` を再直列化してから検査する経路はありません。このため、`actor:1.0` の不正な整数字句が正規化で消えることはなく、未知項目の `1e20`、`1e-400`、巨大な指数字句、高精度小数、明示的な `null`、裏ドラの別名を保存原文として維持します。

解析済みのイベント・注釈を変更しても、原文文字列を入力するencodeの結果へ反映されないことを恒久テストで確認しています。変更したい場合は新しい原文を明示的に渡し、再検査を受ける契約です。JavaScriptの解析値が任意精度になるという保証はありません。

### 構造、字句、深さ

外側は5項目に固定され、未知の項目、欠落、重複、未知版、非オブジェクト注釈を拒否します。版と連番は整数字句を要求し、連番の値域は `1..4294967295` です。イベントの型付き項目にも既存の整数字句・牌表記の検査を適用します。

SDKの既存の上限である1MiB、深さ64、5万ノードは維持されています。包みの追加構造も検査対象です。深さの上限直前の標準イベントや5万ノードの標準イベントが、包装により制限を超えた場合は出力前に拒否されることを確認しました。encodeは生成した包みを再検査するため、「成功した出力を同じSDKが読めない」状態にはしません。包装の追加部分を含めて受理された深さの境界例は、原文を変えずに再読できました。

JSONの前後から除くのはASCIIのJSON空白だけです。NBSPなどを無断で取り除かず、保存する原文内の実CR/LFは拒否します。文字列中のエスケープされた改行表現は維持します。

### 逐次処理、上限、失敗

標準・注釈付きの逐次読み込みは、共通のライフサイクル検査を使用します。注釈付きでは物理行番号と連番も照合します。`end_game` を読んだだけで成功せず、入力を最後まで消費してから完了を報告します。正常な終了イベントの後に入力元が例外を出す対照でも、成功報告は返りませんでした。

入力と出力の双方でUTF-8のバイト数を数えます。単一行encodeの返却文字列にはLFがないため、その文字列だけを数えます。逐次変換は出力LFを総量へ加えます。日本語を含む行の正確な上限、1バイト不足、文字数とバイト数の取り違えを独立に確認しました。

出力先関数の戻すPromiseを各行で待機します。最終行のPromiseを未解決にした対照では変換全体が完了せず、解決後にだけ件数報告を返しました。最終行の書込みが失敗する対照でも成功報告は返りませんでした。途中まで呼び出した出力先の処理を巻き戻す機能ではなく、正常終了前の出力を公開しない責務は呼出側にあります。

## API・公開型・情報公開境界

`AnalyzeMjai.format` の省略時は標準mjaiであり、明示値は `mjai` と `annotated_mjai` だけです。未知値、`null`、値型の誤りは拒否します。形式を暗黙に推測し直す経路はありません。

`Client.analyzeMjai(mjson, viewer?, format?)` は既存の1引数・2引数の呼出しを保ち、省略項目を要求へ追加しません。生成された要求型では `format` が省略可能で、任意JSONを閉じたプロトコル型へ混ぜていません。型検査には誤った形式名、数値解析済みオブジェクトをencodeへ渡す誤用、真偽値でない破棄指定を拒否する例があります。

Rust APIは形式に応じて同じ局面復元処理へ接続し、解析用の状態を要求ごとに構築します。標準と注釈付きの集計・観測は、観戦者と4席で一致しました。通常の対局と学習環境の状態が解析前後で変わらないこと、失敗した解析でも状態が変わらないことを確認しました。返す観測へ原イベントや注釈は含まれません。
