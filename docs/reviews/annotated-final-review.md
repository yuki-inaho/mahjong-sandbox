# 注釈付きmjai：実装レビューの総合記録

## 判定と担当の分離

実装レビューの判定は **PASS** です。原文保持、注釈破棄、既存の標準形式読込みとAPI要求、正常EOF、入出力上限、ファイル公開の境界について、今回の要求を阻害する未解決指摘はありません。これは総合検査・実牌譜全件・配布・CI・マージが完了したという判定ではなく、各結果は [検証記録](../verification/annotated-results.md) と [作業書](../workdocs/workdoc_Nov23-2026_mjai_annotated.md) で別に確認します。

Rust/CLIはSDK担当が、SDK/APIはRust担当が独立レビューしました。実例検査器と配布消費の実装は別担当が作成し、主担当が差分・比較基準・失敗対照・公開情報を確認しました。作業書は独立監査担当がレビューしています。実装者自身のテスト成功だけを独立レビューと呼んでいません。

## 実装中に見つけた反例と解消

| ID | 再現した問題 | 修正と確認 |
|---|---|---|
| CR-01 | 標準readerで受理した内部CRをそのまま包装すると、新形式では再読できない | 保存用の共通出力部分で実CR/LFを拒否。反例の失敗101→成功0、従来の標準readerは維持 |
| SDK-01 | 既存のイベント専用readerも保存用の制限を経由し、内部CRの互換が退行 | 既存readerは従来の解析経路を使い、共通の順序検査を再利用。独立した同じ反例で再確認 |
| SDK-02 | 継承された破棄指定や処理途中の指定変更で、注釈を破棄できる | 呼出時に自身の真偽値項目を一度だけ取得し固定。継承・途中変更・getterを恒久検査へ追加 |
| RCLI-01 | 保存成功後の標準出力だけが失敗すると、公開済みの事実を診断から判断できない | 保存済みの宛先と報告失敗を明記。完成物を保持して再解析可能であり、公開前の失敗では未公開であることを独立再確認 |

初期の失敗は別の証跡として保持します。報告失敗の修正は非0終了を成功へ読み替えるものではありません。保存・検証の失敗と、公開後に報告先が失敗した状態を区別し、実際のファイル状態を利用者へ伝えます。

## 保存・解析・観測の照合

イベントと注釈の保存原文を解析用の数値・型から分けています。未知項目、巨大・微小な受理済み数値、明示null、別名、Unicodeエスケープを再直列化しません。外側の版・キー集合・連番を検査し、イベント原文を従来の構造・意味検査へ渡します。整数字句を浮動小数点から補正して検査を通す経路はありません。

Rustの原文抽出はRawValue、SDKは既存の重複拒否JSONパーサで捕捉した字句範囲を使います。生成する公開Schemaには形式選択の閉じた列挙を追加し、任意の注釈JSONを閉じたAPI型へ混ぜていません。

注釈は局面・集計・観測へ混入しません。赤牌イベント数は既知の牌項目のみを対象とします。固定20件の入力SHAを照合した独立走査で、合計58件が既存の固定期待値と一致しました。期待値を新実装から生成し直して合わせる変更はありません。

## 検査器・配布消費のレビュー

`check_roundtrip` は元と戻した記録の各行に加え、固定変換器のLF付き全バイト列を比較します。数値をJSONへ再解析して期待値を作る方式ではありません。比較の失敗時は内容を公開せず、診断位置だけを返します。

観測比較は各イベント後×4席です。両形式が同じ余計な情報を出した場合も、許可された外側・観測・各家・副露・捨牌項目の集合を検査します。Pythonの真偽値と整数の同値比較で誤って一致しないよう、値の型も区別します。削除、null消去、順序変更、数値丸め、途中観測の変更、同一の情報混入などを拒否する単体29件を確認しました。

母集団は実牌譜由来確認2件と外部回帰18件のままです。各ケースの成功・失敗と未実行を残し、合計2,310イベント・9,240観測を最終成功の必要条件にしています。本文・対局者名・入力全体を検証集計へ転載する経路は追加していません。

配布検査は既存17段階の中で、新しいnativeの原文往復と8イベント×4席32観測、公開SDKの原文・注釈の読書き・明示破棄、Node/Web WASMの各席解析を呼びます。開発ディレクトリでの接続確認と、実際の配布書庫を消費する最終検査を区別しています。

公開前点検で見つかった配布内部の絶対パスは、releaseビルドの子環境に経路置換を追加して是正しました。実書庫の必須native2本・Node/Web WASM2本を検査する処理を追加し、独立担当も正式配布runの現物を別処理で確認しています。初回の不合格と修正後の合格は公開前レビューへ両方残しました。

## 残る制約

Rustの `ParsedEvent` には公開項目 `json`、`Request::AnalyzeMjai` には `format` を追加しています。既存のreader・JSON要求の互換と、構造体・列挙型リテラルを使うRust呼出側のソース互換は別です。直接生成するコードは新項目への対応が必要であり、crateのREADMEに検査済みの `parse_record` / `visit` を使う方法と標準形式の `MjaiFormat::Mjai` を指定する移行方法を明記しました。

入力として従来拒否していた数値を新形式で許可する機能ではありません。SDKの安全整数、1行パーサの上限、Rust/SDKの既存深さ制限を維持します。低水準の保存関数へ渡した途中出力の公開管理は呼出側の責務です。任意の空白・改行・gzip圧縮バイト列の一致、全麻雀規則・得点の独立証明、OSクラッシュ後の永続性は今回の保証範囲に含みません。
