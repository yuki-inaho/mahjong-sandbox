# 現状の辛口レビュー：mjson対応前

対象commit: `c2f5f0f88e83c4cf6698dfad4eba4d9461a2b6d9`。2026-11-23。読取り専用の独立調査と主担当のコード照合に基づきます。

## 判定

既存の独自ログの内部整合性検査は慎重ですが、外部の実牌譜を分析する基盤としては未完成です。独自writerと独自readerが同じcoreで一致することは、外部mjaiとの互換性の根拠にはなりません。

| 重大度 | 指摘と根拠 | 影響 | 対応検査 |
|---|---|---|---|
| 重大 | `logging/types.rs`はrecord識別子の独自6種、`reader.rs`は先頭replay_header固定 | mjaiのtype=start_gameを読めない | 外部固定実牌譜、CLI、TS/WASM |
| 重大 | readerはengine/rules/shuffle/seedからGame::newを呼ぶ | 外部配牌・ツモを再現できず、全規則合法性を主張できない | 外部イベント状態の復元とcore完全再生の能力を分離 |
| 重大 | coreの牌型は34種類、赤なし・頭ハネで加槓等未対応 | 外部牌譜を直接押し込むと情報が失われる | 赤牌・未知牌・加槓・複数和了を独立型で保持 |
| 重大 | `tests/logging.rs`は自作coreから作った入力を自作coreで再生 | 実データのイベント順序や意味の間違いを検出できない | 元データ識別子と固定期待値を持つ事例検査 |
| 重大 | `protocol.rs`、WASM、SDKに外部牌譜分析入口がない | Rustにパーサを足すだけでは利用できない | 公開要求・生成型・SDK・実WASM検査 |
| 軽微 | 意味エラーに行番号がない | 後半の破損箇所をAIエージェントが特定しにくい | 行番号とイベント型付き診断 |
| 軽微 | public_stepが毎操作GameView全体を保持 | 捨牌・副露列の反復で冗長 | 意味イベント出力、同じ対局でbyte数測定 |

## 再現

既存 `suzume-api replay examples/replay-eight-actions.jsonl` は8操作、truncated、全員25,000点で成功しました。mjaiのstart_game/end_gameを入力すると `invalid log record at line 1: missing field record` で失敗しました。サンプルの2行目と7行目のafter_sha256を改変すると、どちらも同一の行番号なしエラーでした。

これは既存ビルドで確認した部分再現です。新規全検査の結果は新しい作業書と検証結果で別に記録します。既存76件等の過去件数を今回の実行数として引用しません。

## 維持する設計

既存の入力上限、入れ子の重複キー拒否、原子的な最終ファイル公開、I/O失敗後のwriter禁止、共有観測の情報制限には具体的な防御があります。今回の移行でもこれらを失わないことを受入条件とします。内部のPassと採用されなかった応答は外部の副露イベントではありません。
