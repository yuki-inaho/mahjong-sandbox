# 文書の書き方

初めて使う人には始め方を、組み込む人には仕様を、変更する人には検証方法を示します。説明の詳しさは、その文書を読む目的に合わせます。

## 情報を置く場所

| 文書 | 載せる内容 |
|---|---|
| ルートREADME | 目的、最短の起動手順、基本操作、目的別の文書リンク、参考リンク |
| 各README | その場所でできること、最初の使い方、詳しい仕様への案内 |
| 遊び方・利用手順 | 必要な環境、操作の順序、入力、結果、困ったときの設定 |
| 仕様書 | 対象、用語、設定値、入出力、制限、エラー時の動作 |
| 開発文書 | 使用するスキル、検証コマンド、結果の判定と保存方法 |

READMEの見出しに製品バージョンや実装言語を付けません。導入に必要なツール版や、互換性に関係するAPI版は、必要な手順・仕様に記載します。作業書や検収履歴は一般向けの案内へ並べません。

## 日本語の説明

一段落では一つの話題を扱い、最初の文で対象を示します。見出しは「起動する」「牌譜を解析する」など、読者が探している操作や内容に合わせます。抽象的な評価より、入力・処理・結果を書きます。

用語は初出で説明し、同じ対象には同じ名前を使います。`suzume-api` や `@mahjong-sandbox/sdk` のような識別子は実装どおりに書きます。数字や条件を削って意味を変えず、未対応・未確認の範囲も該当する仕様に残します。

操作の順序には番号付きの手順、設定や用途の対応には表を使います。リンク名は遷移先の内容が分かる表現にし、リポジトリ内の文書には相対リンクを使います。単独で配布するパッケージのREADMEから、同梱しない文書へ案内するときはリポジトリのURLを使います。

## 改稿後の確認

元の説明と比べ、条件・単位・制限・エラー時の結果が保たれていることを確認します。移動した説明には案内を付け、同じ仕様を複数の場所で詳述しません。牌譜の記録終端と正常終局、構造検査と麻雀規則の検証など、判断に関係する違いは残します。

[文章レビューのスキル](../../skills/review-writing-clarity/SKILL.md)を読み、読者が文書だけで目的の操作へ進めるか確認します。リンク・見出し・掲載コマンドの静的検査は、リポジトリのルートで実行します。

```sh
python3 scripts/check_documentation.py --json
git diff --check
```

この検査は、外部URLの疎通や掲載した全コマンドの実行成功を保証しません。文書だけの変更では、内容を実装と照合したうえで必要な確認を選びます。
