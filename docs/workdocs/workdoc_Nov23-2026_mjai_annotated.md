## 1. 作業目的

### 1.1 ゴール要求分析

利用者の目的は、標準mjsonを用いる麻雀ログへ解析理由や評価を付け、別のツールでも利用できる標準形式へ戻せることです。前回のmjson移行はPR #1でマージ済みです。今回の「続けて」という依頼を、従前に許可された形式間の変換・拡張用の包装を具体化する作業として進めます。調査と辛口レビュー、write/reviewスキルによる作業書、実例に基づくTDD、ブランチ作成からマージまでという条件を継続します。

明示要求は、実用的な拡張性と相互変換、AIが扱えるパーサ、実牌譜による事例検証、調査・レビュー・作業記録、検証後のマージです。今回の成功は、受理したイベント原文を失わずに標準→注釈付き→標準を往復でき、注釈の明示的な追加・読出しができ、同じイベントの解析と観測が一致することで判定します。

暗黙制約は、既存のmjson既定出力と旧replay変換を維持し、観測へ他家の秘密情報を混ぜないこと、入力・出力の上限と正常終端を検査すること、無断の値補正や形式の暗黙推測をしないことです。Rust/Cargo、TypeScript/Node、WASM、Python補助処理を使用します。Pythonは `uv run --no-project` で実行し、このリポジトリに存在しないuv lockやDocker環境を要求しません。DRY/KISS/SOLIDと失敗先行のテストを適用します。

対象外は、全mjai方言への適合、三麻、全役・点数の独立再計算、AI強度向上、mjsonにない乱数種・内部操作の復元、注釈を捨てた後の復元です。元イベントの内部の原文は保持しますが、圧縮バイト列、行前後の空白、改行方式の一致は要求しません。Rust/SDKの既存数値受理範囲は維持し、解析値の近似表現と保存原文を区別します。

リスクは、数値の再直列化による丸め、nullや別名の消失、包むことで整数字句検査を迂回する実装、注釈による集計汚染、途中出力の公開、実牌譜本文の漏出です。それぞれを仕様と名前付きの負例へ対応させます。公開済み履歴や前回の検証記録は書き換えません。

## 2. 作業内容

### フェーズ1：調査・設計（手順1〜4）

基準commitの `mjai/{reader,types,state}.rs`、SDKの `mjai.ts` / `validation.ts`、CLI、外部事例検査を読みます。既存の `Value` / `Number` からの再生成が原値を保持しないことを合成プローブで確認しました。具体例は [現状レビュー](../reviews/annotated-baseline-review.md) に記録します。保存の正本は原イベントのJSON原文とし、閉じた外側5項目の契約を [仕様](../logging/annotated-mjai.md) と [ADR](../adr/0008-annotated-mjai.md) に固定します。

SDKの逐次変換名は `wrapMjaiRecords(chunks, write, limits?)` と `unwrapAnnotatedMjaiRecords(chunks, write, options?, limits?)`、単一行の保存名は `encodeAnnotatedMjaiRecord` です。変換関数は `write: (line: string) => void | Promise<void>` へLF付きの行を渡し、正常EOF後に `Promise<MjaiTranscodeReport>` を完了して `{ records, droppedAnnotationRecords }` で件数を返します。出力は正常完了まで暫定です。unwrapのoptionsは `{ dropAnnotations?: boolean }`、既定はfalseです。Rustの単一行encodeは `encode_record(event_json, index, annotations_json, limits)`、文字列はLFなしを返します。原文は出力前に検証し、任意に変更された解析値を信頼しません。

indexの範囲は全実行環境で `1..=4294967295` に固定します。単一行encodeは前後のJSON ASCII空白だけを除き、原文内部の実CR/LFを拒否します。エスケープ済みの改行は保持し、NBSPをtrimして不正JSONを有効化しません。抽出イベントを既存の構造・深さ・整数字句検査へ通します。

入出力上限はUTF-8バイト数です。行上限は終端LFを除き、総量はLFを含めます。入力CRLFのCRは行上限に含めます。包装による追加分も出力上限へ含めます。

### フェーズ2：実装（手順5〜12-b）

名前付きの事例を先に追加し、初期失敗を保存します。Rust担当はmjaiモジュールとRust事例、SDK担当はprotocol/libとSDK・生成物・型/WASM事例、独立監査担当は実例検査と配布消費、主担当はCLI・文書・GitHub公開を担当します。各担当のファイルを重複して編集しません。準備は並行できますが、正本の完了印は主担当が手順の順に一項目ずつ検収して更新します。

新しいRustの `ParsedEvent.json` とSDKの `eventJson` / `annotationsJson` が原文保持を担います。Rustの単一行parse、注釈付きvisit_records、encodeが注釈を読書きする経路です。複数行の意味検査は既存ReplayStateを使います。新しいformat列挙だけをプロトコル生成対象へ追加し、任意JSONを公開Schemaへ混ぜません。

#### 先に固定する事例

| 分類 | 事例・期待 |
|---|---|
| 原文保持 | `9007199254740993e0`、`1e-400`、`1e20`、高精度小数、Rustの巨大整数、明示null、未知入れ子、裏ドラ別名、キー順が往復で同じ |
| 構造拒否 | 未知版・未知外側項目・欠落項目・重複キー・非object注釈・index欠落/重複、`schema_version:1.0`、`actor:1.0` を拒否 |
| 注釈 | 非空注釈の既定unwrapを拒否、明示破棄で行数を報告、注釈原文を読書きできる |
| 集計境界 | 名前や任意追加情報・注釈の `5mr` はred_eventsへ影響せず、既知牌項目の赤牌は数える |
| 完全性・資源 | 終端欠落、終端後追記、破損gzip、行・件数・総量上限、出力側だけの上限超過、I/O失敗を拒否 |
| 公開 | 完成物の非上書き、失敗時の未公開・一時ファイル削除、4席観測へ原文や注釈を混ぜない |
| API互換 | format省略時の標準mjson、明示された2形式の同一結果、未知format拒否、セッション非変更 |
| 検査器 | 1項目の削除、null消去、順序変更、1件の欠落を注入した対照が失敗する |

#### 固定した実牌譜の母集団

`tests/fixtures/mjai/manifest.json` の20事例を全件使用します。参照先は `NikkeTryHard/tenhou-to-mjai` のcommit `f08b4e0f7d96b57d0099b9b2e5eb6dd5c4e5f4eb` です。実牌譜由来を確認した `ranked_game`（316イベント・3局）と `suukantsu_1`（243イベント・2局）、外部回帰18件で、全体は2,310イベント・23局です。20件すべてが実在の完全対局であるとは表現しません。成功事例だけの選び直し・除外は行いません。

既存の元データ・変換後SHAと局数・最終持点は変更しません。今回の往復の正解は元の各イベント原文です。全体のbyte列と各行を比較し、集計と4席すべての観測は標準入力時と注釈付き入力時を比較します。対象は各イベント後の2,310×4＝9,240観測であり、最終観測だけではありません。これは相互変換の保持検査であり、全局面を別の麻雀実装で正解判定した証明ではありません。red_eventsの新定義は既知牌項目の独立走査で固定期待値と照合し、必要な差分が出た場合だけ原因を記録します。

生データ、変換物、観測は `dist/mjai-real/` に限定します。公開可能な `dist/verification/` とリポジトリ文書には件数、SHA、終了コード、診断位置だけを保存します。CI artifactや配布書庫へ牌譜本文・対局者名を含めません。取得失敗・hash不一致は失敗であり、省略して全成功としません。
