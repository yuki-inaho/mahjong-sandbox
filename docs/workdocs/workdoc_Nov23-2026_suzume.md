## 1. 作業目的

### 1.1 ゴール要求分析

端末で実際に遊べるRust製の麻雀を独自実装し、宣言したルールと実行コードの対応を検査・証明できる開発基盤を作ります。

明示要求は、Rust、独自実装、TUI、Kani、Lean、宣言的なルール、契約に基づく処理、SOLID/KISS/DRY、可搬性・保守性・再利用性、構造化したコンセプト文書、ADR、作業書の作成・レビュー・完了までの継続、指定リポジトリへの定期的なコミット・pushです。

前提として、初版の対局規則は日本式四人リーチ麻雀、対戦は人間1人とCPU3人、通信対戦は含めません。赤牌や途中流局などの採否は `rules/riichi.rules` に明示し、未対応機能を可能と表示しません。参照先のコードを流用せず、公開された説明と設計上の考え方を参照します。Rust標準ライブラリを基本とし、端末表示と入力を対局処理から分離します。

成功条件は実際に操作できる対局、状態を壊さない不正操作の拒否、役・符・点数の例に基づく検査、Kaniの成功、Leanの成功、宣言の同期検査、対応表と実行証跡の保存です。Lean単体でRust全体の意味論を証明したとは扱いません。Leanの抽象仕様とKaniが検査するRust関数の対応範囲を明示します。

最初の環境調査ではRust等が未導入でした。公式配布物を作業用領域へ導入し、Rust 1.100.0、Kani 0.68.0、Lean 4.36.0の独立した動作確認が成功しています。これはアプリ本体の成功とは区別します。外部配布物の取得失敗、ソルバーの計算量、複数の和了形と符計算が主なリスクです。

## 2. 作業内容

### フェーズ1：計画と調査（SG-1、TR-01〜08）

指定スキルを照合し、この作業書をレビューします。麻雀4件、Kani、Go-Leanの公開文書を確認し、初版の規則と形式検証の境界を明文化します。元のスキルはuv向けですが、利用者指定のRustプロジェクトであるため主コマンドはCargo/Lakeとします。補助Pythonは依存ゼロのスクリプトを `uv run --no-project` で実行できます。保存先は明示指示どおり `docs/workdocs/` です。

### フェーズ2：設計と実装（SG-1〜3、TR-01〜06）

宣言・契約・形式仕様を先に定めます。牌と判定、対局遷移、CPUと端末表示を別モジュールに実装します。補助担当は独立した成果物を準備できますが、主担当が下記の順で検収します。主担当だけが本書の完了印を変更します。

### フェーズ3：検証と公開（SG-3〜4、TR-01〜08）

Rustテスト、形式検証、複数の乱数種による対局、実端末での入力、構造と公開差分のレビューを行います。失敗は修正し、影響する検査を再実行します。検証結果・制約を記録し、区切りごとに指定先へpushします。

## 4. 作業に使用するコマンド参考情報

リポジトリルートで `cargo run --release`、`cargo run --release -- --simulate 32 --seed 0`、`cargo test`、`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo kani` を使用します。Leanは `proofs/` で `lake build` します。補助検査は `uv run --no-project scripts/verify.py` を入口とします。最終コマンド仕様はREADMEと照合します。

### 検査の失敗先行と証跡

新規モジュールは意味のある境界テストを先に作ることを基本とします。実際に観測した失敗のみを `docs/verification/logs/red-*.txt`、修正後を別の成功ログへ保存します。後から意図的に壊した検査は否定検査であり、実装前のTDD失敗とは呼びません。表内の名前は計画名であり、最終対応表では実装されたテスト名へ対応付けます。

| 対象 | 期待する初回の失敗 | 成功の検査 |
|---|---|---|
| 牌の構築 | 不正IDを通す、または構築関数が未実装 | invalid_tiles_are_rejected |
| 牌移動 | 枚数不足や5枚目を許す、保存条件を破る | move_one_preserves_sum |
| 点数移動 | 範囲外、オーバーフロー、途中変更を許す | transfer_points_is_atomic |
| 和了形 | 三形のいずれかを誤判定する | standard_seven_pairs_orphans |
| 役と符 | ドラだけを役とする、平和ツモを誤計算する | no_yaku_is_rejected / pinfu_tsumo_twenty_fu |
