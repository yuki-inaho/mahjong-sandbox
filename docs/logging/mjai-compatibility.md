# 外部mjson牌譜との互換性と実例検査

本対応では、対局イベントを1行1個のJSONとして表すmjai形式を `.mjson` として扱います。
参照実装は [NikkeTryHard/tenhou-to-mjai の固定コミット](https://github.com/NikkeTryHard/tenhou-to-mjai/tree/f08b4e0f7d96b57d0099b9b2e5eb6dd5c4e5f4eb) です。
元の通信形式は [Mjai公式説明](https://gimite.net/pukiwiki/index.php?Mjai%20%E9%BA%BB%E9%9B%80AI%E5%AF%BE%E6%88%A6%E3%82%B5%E3%83%BC%E3%83%90) を参照します。
対象は四人麻雀の牌譜イベントです。TCP接続、`hello`、`join` などの通信接続手順は対象外です。

## 保存形式と読み込み

非圧縮のUTF-8 JSON Linesを標準の出力とします。各行は `type` を持つオブジェクトです。
CRLFと末尾改行のない最終行を受け付けます。重複したJSONキー、壊れたJSON、無効な牌、範囲外の席番号、
局の開始・終了や持牌消費に矛盾するイベントを拒否します。エラーには行番号と、取得できた場合はイベント種別を付けます。

参照先の配布データには、拡張子が `.mjson` のままでgzip圧縮されたものがあります。
CLIのファイル入力は先頭バイトで圧縮を判別します。実例検査では同じ牌譜を非圧縮とgzipの両方で渡し、
同じ集計になることを確認します。Rustの `BufRead` に対する解析関数は展開済みのテキストを入力とします。
WASM・APIへ文字列として渡す場合も事前に展開してください。

## 牌とイベントの契約

牌は `1m`〜`9m`、`1p`〜`9p`、`1s`〜`9s`、字牌 `E/S/W/N/P/F/C`、赤五 `5mr/5pr/5sr`、未知牌 `?` です。
赤五と通常五、未知牌と既知牌を区別して保持します。席番号は0〜3、局番号は1〜4です。

| イベント | 主なフィールドと意味 |
|---|---|
| `start_game` | 対局開始。名前などの付加情報を持てます。 |
| `start_kyoku` | 場風 `bakaze`、局 `kyoku`、本場 `honba`、供託 `kyotaku`、親 `oya`、点数 `scores[4]`、配牌 `tehais[4][13]`、表ドラ表示牌 `dora_marker`。 |
| `tsumo` | 引いた席 `actor` と牌 `pai`。他家に見せない牌は `?` にできます。 |
| `dahai` | `actor`、`pai`、ツモ切りを表す `tsumogiri`。 |
| `chi` / `pon` | `actor`、捨てた席 `target`、取った牌 `pai`、手牌から消費する2枚 `consumed`。 |
| `daiminkan` | `actor`、`target`、`pai`、手牌から消費する3枚 `consumed`。 |
| `ankan` | `actor`、消費する4枚 `consumed`。 |
| `kakan` | `actor`、追加する1枚 `pai`、既存のポンの3枚 `consumed`。 |
| `dora` | 新たな表ドラ表示牌 `dora_marker`。 |
| `reach` | リーチ宣言。成立前なので、このイベントだけでは供託を増やしません。 |
| `reach_accepted` | リーチ成立。該当席の1,000点を供託へ移します。 |
| `hora` | 勝者 `actor`、相手 `target`、任意の点数差 `deltas[4]`、任意の裏ドラ表示牌。`actor == target` はツモです。 |
| `ryukyoku` | 流局。点数差 `deltas[4]` は省略可能です。 |
| `end_kyoku` / `end_game` | 局・対局の終了。 |
| `none` | 動作のないイベント。 |

型の一次資料は、固定版の [mjai.rs](https://github.com/NikkeTryHard/tenhou-to-mjai/blob/f08b4e0f7d96b57d0099b9b2e5eb6dd5c4e5f4eb/crates/convlog/src/mjai.rs) と [tile.rs](https://github.com/NikkeTryHard/tenhou-to-mjai/blob/f08b4e0f7d96b57d0099b9b2e5eb6dd5c4e5f4eb/crates/convlog/src/tile.rs) です。
以下の派生差を吸収します。

- 参照変換器の `hora` は、勝ち牌・役・符・飜・絶対点数を省略します。これらを必須にしません。
- `ura_markers` と元Mjaiの `uradora_markers` を同じ裏ドラ表示牌として読みます。
- `reach_accepted` は席番号だけでも受け付けます。
- `start_game` の `kyoku_first` / `aka_flag`、役の説明、任意の付加情報は元オブジェクトに保持します。
- `deltas` がない場合、点数と供託の集計は未知として返します。差分ゼロを仮定しません。
- 同じ打牌または加槓に対する複数ロンの `hora` を保持します。最初のロンで局を閉じません。ツモ和了後の追加和了は拒否します。
- 暗槓、加槓、大明槓のドラ表示の順序は同一ではありません。槍槓で追加ドラの出現前に局が終わる場合も扱います。

三人麻雀の抜きドラ `nukidora` や未定義のイベントは、読み飛ばして成功扱いにせず拒否します。
既知イベントの付加情報保持は、未定義イベントの意味解析に対応したことを意味しません。

## AIエージェントから使う場合の境界

各イベントの解析後に、当該時点の観測を席別に取得できます。自分の手牌と他家の公開情報を区別します。
観戦者には非公開の手牌を渡しません。元のイベント本文には全員の配牌・ツモが含まれ得るため、
不完全情報のAI評価には元イベントの全文を入力せず、視点を指定した観測を用いてください。

外部の牌譜を読めることと、すずめの対局コアで同じ規則を完全に再演できることは別です。
外部形式の赤牌・加槓・複数ロンなどを読み取り、記録された局面と点数差を追跡しますが、
外部の役・符・採用規則すべてを再判定するものではありません。勝ち牌や役の省略もあるため、
この解析結果だけから未実装規則の合法性やAIの強さを主張しません。
この検査ではXMLの直接変換を行わず、外部の天鳳JSONを固定版変換器でmjsonへ変換します。

## 事例の選定と固定した期待値

[manifest.json](../../tests/fixtures/mjai/manifest.json) に原本の固定URL、SHA-256、変換後SHA-256、
イベント数、局数、最終点、種類別件数を記録しています。牌譜本文は含みません。
固定版の `crates/convlog/tests/testdata` にある20個のJSONをすべて選択し、除外はありません。
2件は元の実対局識別子と最終成績を持つ対局、18件は外部変換器の局単位の回帰素材です。
後者すべてについて独立した実対局IDまで確認できたとは主張しません。

| 種別 | ケース | イベント数 | 局数 | 最終点 |
|---|---|---:|---:|---|
| 実対局 | `ranked_game` | 316 | 3 | 21100 / 55000 / -4900 / 28800 |
| 実対局 | `suukantsu_1` | 243 | 2 | 38000 / 29000 / -24000 / 57000 |
| 回帰素材 | その他18件 | 1751 | 18 | ケースごとにmanifestへ固定 |
| 合計 | 20件 | 2310 | 23 | 初期点数・供託は各局の宣言を採用 |

選定した資料には、チー14回、ポン62回、大明槓4回、暗槓2回、加槓10回、追加ドラ13回、
リーチ宣言12回、リーチ成立10回、和了20件、流局5件があります。
通常対局と合計120,000点の大会設定、宣言牌でのロン、四家立直、嶺上、槍槓、連続するロンを含みます。
和了数は勝者ごとの `hora` 数なので、和了した局数とは一致しない場合があります。

`calls` はチー・ポン・大明槓・暗槓・加槓のイベント合計です。
`red_events` は既知の牌項目に赤五表記があるイベントの数で、赤牌の枚数や固有牌数とは異なります。
名前・未解釈の追加項目・注釈の文字列は数えません。以前の原JSON全体を数える定義から変更しました。
対象となる牌項目と原文保持の契約は [注釈付きmjai仕様](annotated-mjai.md) に記載しています。
実対局2件では、元JSONの `sc` から得た最終点も解析結果と独立に照合します。
残り18件の点数は固定した変換イベントと宣言された精算を根拠とするため、この独立性を過大に主張しません。

## 再実行

Git、Rust 1.100.0、Python 3.12.10を用意し、リポジトリ直下で次を実行します。
追加のPythonパッケージは不要です。

```sh
python scripts/verify_mjai_real.py
```

検査器は次の順に実行します。

1. 固定コミットを `dist/mjai-real/upstream` に取得し、コミット、作業ツリー、`Cargo.lock` を照合します。
2. 参照先の既存 `tenhou2mjai.rs` をconvlogのexampleとして配置し、`cargo build --locked` で構築します。
3. 本リポジトリの `suzume-api` を構築します。
4. 全20件の原本SHA-256、変換後SHA-256と件数、解析結果の期待値を照合します。
5. 全20件を注釈付き形式へ包んで標準mjsonへ戻し、全2,310イベントの原文・順序・固定SHAを照合します。
6. 両形式の集計と各イベント後の4席の観測、計9,240観測を比較します。既知牌項目から独立集計した赤牌イベント数も固定期待値と照合します。
7. `ranked_game` の標準・注釈付き入力をgzip圧縮して拡張子を `.mjson` とした場合にも、それぞれ同じ結果になることを確認します。
8. 本文を含めない実行日時別の集計を `dist/verification/` に保存します。

取得済みの参照リポジトリは `--upstream`、構築済みの解析用実行ファイルは `--binary` で明示できます。
参照先を再利用する場合も、固定コミット・未改変・`Cargo.lock` の照合を省略しません。
解析用実行ファイルはSHA-256を記録します。`--binary` を指定した場合は再構築しないため、
検査対象の実行ファイルを取り違えないでください。
`--report` では `dist/verification/` 以下の新しいJSON保存先を指定でき、既存証跡の上書きは拒否します。

取得・構築・変換・解析にはそれぞれ制限時間があります。失敗と時間切れは非ゼロ終了となり、
取得失敗を無視したり、成功したケースだけへ母数を縮小したりしません。
原本や変換結果のハッシュが一致しない場合は参照先更新として自動採用せず、原因を確認してから
入力・期待値・互換性判断を同じ変更としてレビューしてください。

検査器自体の改変・欠落・誤集計・時間切れ検出は次のコマンドで確認できます。

```sh
python scripts/tests/test_mjai_real.py
```

## データの取り扱いと検査記録

参照先の [LICENSE-DATA](https://github.com/NikkeTryHard/tenhou-to-mjai/blob/f08b4e0f7d96b57d0099b9b2e5eb6dd5c4e5f4eb/LICENSE-DATA) は、牌譜に対するライセンス付与・明示的再配布許諾がないと記載しています。
[天鳳公式の配布説明](https://tenhou.net/sc/raw/) にも牌譜の用途と再配布について制約があります。
コードのApache/MITライセンスを、牌譜の再配布許可と読み替えません。
本リポジトリは外部牌譜本体を収録せず、検査時の取得物・変換結果を `dist/mjai-real/` に限定します。
利用時は原配布元の条件を確認してください。

専用の [CI](../../.github/workflows/mjai.yml) は検査集計JSONだけを成果物として保存します。
原本、変換済み牌譜、参照リポジトリ、ビルドキャッシュはアップロードしません。
検査器は子プロセスの生出力を集計へ転載せず、対局者名、対局ID、牌譜本文、実行環境の絶対パスを記録しません。
同じデータの変換前後が一致したという検査と、すずめの状態復元が固定期待値と一致したという検査を区別して記録します。

検査用の合成局面は [Rustパーサ試験](../../crates/suzume-api/tests/mjai_parser.rs) に置きます。
これらを外部の実牌譜に数えません。初回移行の結果は [mjson作業書](../workdocs/workdoc_Nov23-2026_mjson.md)、原文往復と注釈付き記録の失敗先行・修正後の結果は [追加作業書](../workdocs/workdoc_Nov23-2026_mjai_annotated.md) から参照します。
