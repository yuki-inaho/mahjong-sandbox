# ADR-0004：対局コア、アプリケーションAPI、表示と配布の境界

日付：2026-11-23。状態：採用。実行結果は追加作業書と検証記録で別管理します。

## 背景

初版は端末で動きますが、`Game`には全員の手牌、山、再現用の乱数種、応答中の選択が含まれます。公開getterは信頼するRust呼出し元向けで、これをそのままJSON化すると閲覧席の区別がありません。また、席・手牌添字の不正値でpanicする経路、検証用の生成仕様の過大な公開範囲がありました。初版の形式検証は6契約の限定した入力域であり、これらの外部APIの安全性を示していません。

利用者は別のJS/TSフロントエンド、再現環境、配布、型情報、探索・強化学習への拡張を求めています。

## 比較と決定

| 案 | 利点 | 判断 |
|---|---|---|
| Gameを直接直列化 | 作業が少ない | 非公開情報と内部表現が外部契約になるため採用しない |
| HTTPサーバーを最初に必須化 | 複数端末から呼べる | 今回のローカル・埋込み用途には認証/運用を持ち込むため対象外 |
| 型付きAPIをnativeとWASMで共有 | 画面と実行環境を替えても同じ契約を使う | 採用。入出力変換は薄い境界へ集約 |

- `suzume`は標準ライブラリだけの対局・判定・算法を提供します。
- `suzume-api`はserdeによる外部入力、TOML、観測、環境、ログを扱います。
- `suzume-cli`はAPIの構成・ログを再利用する端末アプリです。依存の循環を避けるため、初版のmain/uiをここへ移します。
- `suzume-wasm`は同じAPI Engineの呼出しだけを公開します。
- TypeScriptの型と実行時検査はRustのデータ型から生成したJSON Schemaを使います。生成器が扱えないschema構造は黙ってanyへ変換せず拒否します。

APIは版1、エンジンは0.2.0です。入力の席・牌・手牌番号・seedを検査し、操作にはsession_idとexpected_revisionを要求します。ゲームを開始し直した古い操作も拒否します。エラーコードは表示文言から独立した列挙です。

通常セッションのviewerは初期化時に固定します。他家の手牌・山・seed・他家の応答内容を応答へ含めません。これはローカルAPIの情報設計であり、同じプロセスを操作できる利用者に対する秘密保護やオンライン認証ではありません。

## 互換性と検査

coreの不正席を拒否するため`seat_wind`はOptionを返します。このRust API変更は0.2.0の変更として明示します。APIの型、JSON Schema、TS型、WASMの実応答を結合検査します。古いrevision、未知項目、過大入力、再初期化後の操作、非公開情報の漏れを負例に含めます。

外部依存を導入するのは変換・配布の層です。麻雀の判定や戦略を他ライブラリへ置き換えません。WASMのweb/Node出力は[公式の配布方式](https://wasm-bindgen.github.io/wasm-bindgen/reference/deployment.html)、直列化の未知項目拒否は[Serde公式仕様](https://serde.rs/container-attrs.html)に従います。
