# ADR 0008：原イベントのJSON原文を保持する注釈付きmjai

- 日付：2026年11月23日
- 状態：採用。実装と受入の完了は作業書で別に判定します。
- 基準：`d44f5ee499102fd35d81fbba5eb1e42da2e0a318`
- 関連：[前回の判断](0007-mjai-records.md)、[仕様](../logging/annotated-mjai.md)、[調査](../reviews/annotated-baseline-review.md)

## 解決する問題

標準mjsonの読み込みと自作対局の出力は前回の変更で使用できます。利用者が求めた、解析説明などの追加情報を付けて保存し、標準形式へ戻す経路はまだありません。解析用の `Value` / `Number` を保存用にも使うと、受理済みの `9007199254740993e0` や `1e-400` が別の値・表記へ変わります。型付きイベントからの出力は追加項目や明示nullを失います。

## 選択肢と判断

| 選択肢 | 得られるもの | 採否の理由 |
|---|---|---|
| 標準イベント内へ独自項目を追加 | 既存読込みで扱いやすい | 保存用の注釈と生産者の追加情報の境界が曖昧になるため、今回の主形式にはしない |
| 値へ解析して包装・再保存 | 実装量を抑えられる | 数値の丸め・null/別名の消失を再現したため不採用 |
| 原文を別文字列として包装 | 原文の保持が容易 | 二重符号化で一般的なJSON処理からイベントを扱いにくくなるため不採用 |
| オブジェクトのまま包装し、内部の原文範囲を保持 | 標準のJSONとして扱え、原文をそのまま取り出せる | 採用。RustのRawValueとSDKの字句範囲を利用 |

1行単位の `annotated_mjai` 版1を採用します。ヘッダー・フッターや変換器の登録機構は設けず、5項目の閉じた外側と、自由な注釈オブジェクトで用途を満たします。標準mjsonの既定出力と旧replay→mjsonは維持します。

## 帰結

解析用の値には丸めがあり得ることを明示し、保存用の正本を原文に限定します。包装を外す際、非空注釈の破棄は明示指定にし件数を報告します。逐次処理と出力上限を維持し、ネイティブCLIは正常終端後にだけ公開します。公開プロトコルには形式選択の閉じた列挙だけを追加し、任意JSONをSchema生成器へ持ち込みません。

注釈の内容を信用して集計や視点別観測を書き換えません。赤牌集計は既知の牌項目へ限定し、以前の原JSON全体を走査する契約からの変更を仕様へ記録します。数値受理範囲や麻雀の意味検査の範囲は従来どおりです。

## 採否を支える検査

原文を保持する往復、`actor:1.0` の拒否、注釈破棄の明示、入力と出力の上限、破損入力での非公開、全20事例の原文・集計・観測一致を受入条件にします。結果は [作業書](../workdocs/workdoc_Nov23-2026_mjai_annotated.md) へ追記します。
