# ADR-0007：対局の交換・分析形式をmjaiへ移行する

- 状態：採用、実装と検証中
- 日付：2026-11-23
- 対象：0.2系列の追加機能。APIの既存要求と旧replay/publicの読込みを保持する
- 関連：[作業書](../workdocs/workdoc_Nov23-2026_mjson.md)、[現状レビュー](../reviews/mjson-baseline-review.md)、[従前の判断](0005-game-records.md)

## 背景

現行JSONLは内部操作と乱数種を記録し、同じcoreで正確に再生できます。一方、外部の牌譜は配牌・ツモ・打牌・副露などのイベントであり、内部の見送り応答や独自の山生成規則とは対応しません。既存テストの自己一致だけでは外部形式との互換性を確認できません。

利用者は、NikkeTryHard/tenhou-to-mjaiを参考に、mjsonへの置換、AIエージェント向けパーサ、実牌譜でのテスト駆動開発を要求しています。

## 決定

通常の対局出力を `mjai` にし、拡張子には `.mjson` を用います。UTF-8で1行1個のJSONオブジェクト、識別子は `type` です。公開用には `mjai_public` を用意し、配牌とツモの伏せ牌を `?` に置換します。内部の配列添字、乱数種、非公開の判断説明はmjsonへ含めません。

`replay` と `public` は既存の明示的な互換形式として保持します。独自coreの完全再現、189行動IDの学習用遷移、AI判断の詳細記録には引き続きreplayを使えます。旧replayの全検査を経てmjsonへ変換する入口を用意します。mjsonから失われた乱数種や見送りを推測してreplayを作りません。

外部イベントには独立した型を用意します。赤五・未知牌・加槓・複数和了を保持し、coreの34牌種や限定ルールへ押し込みません。型付きの既知フィールドと、追加フィールドを含む元JSONを併せて扱います。未知のイベント型は明示的なエラーです。

Rustの解析器は、入力上限、重複キー、型、イベント順序、手牌・副露の移動、点数と供託を検査します。保存されていない得点や牌は不明として扱います。得られるのは記録に基づく局面であり、全ての和了役・振聴・採用ルールをcoreで検証したという意味ではありません。観測APIは指定席の手牌と公開情報だけを返します。合法手maskは、外部規則を判定していないため作りません。

TSのイベント読み込みは構造検査とストリームの完了確認を行い、意味解析は同じRust実装をCLIまたはWASM経由で呼びます。生成した型と実WASMの結合を検査します。

## 出力上の境界

自作coreの開始状態には親の最初のツモが含まれるため、writerは `start_kyoku` の各13枚と、親の `tsumo` を分離します。内部のPassや不採用の鳴きは出力せず、解決済みの副露・和了だけを出します。立直宣言と成立も分離します。

coreは同種の牌に物理IDを持ちません。そのため同種牌が複数あるとき、ツモ牌と同種の打牌を `tsumogiri=true` とする等価な表現を用います。物理的にどの一枚を捨てたかまで保証するものではありません。外部牌譜を読むときは元のtsumogiriと赤牌を保持します。

標準の `end_game` は局終了後だけを正常終了とします。操作上限や手動中断では `end_game` に `_suzume.reason` を `truncated` または `interrupted` として追加し、解析結果の `complete` はfalseです。標準イベントに拡張を加えるだけで、未完局へ架空の和了・流局を追加しません。最終得点 `scores` と `_suzume.kyotaku` により、coreが終局時に残供託を首位へ渡す精算も表現します。任意の得点上書きを許すものではなく、供託を含む保存則を検査します。

`_suzume` はこの実装の追加メタデータ用です。途中中断を扱わない外部消費者には、通常終局の牌譜を渡してください。

## 圧縮・破損・公開

参照先の配布データにはgzip圧縮された `.mjson` があるため、CLIは拡張子ではなく先頭バイトで判定します。Rustの行パーサ自体は展開済み `BufRead` を受けます。展開後にも行・総量・件数の上限を適用し、壊れたgzipと過大入力を拒否します。

消費者へ渡した途中イベントは暫定結果です。変換・観測出力のファイルは、末尾とEOFまで検証後に確定します。I/O失敗後のwriterは再利用できません。通常の対局ログは途中失敗時に不完全なファイルが残り得るため、完全解析器はその入力を拒否します。

実牌譜は固定URL/commit/SHA256から検証専用に取得します。データ本体をGit、配布書庫、CI artifactへ含めず、公開するのは再取得手順、ハッシュ、匿名の期待値と実結果です。合成境界例と実対局IDのある事例を区別します。

## 代替案と結果

独自形式の拡張子だけを変更する案は、外部互換性がないため採りません。全てを標準イベントに置換して独自再生機能を捨てる案は、既存の再現・判断・学習用途を失うため採りません。全麻雀ルールを拡張してから取り込む案は、牌譜を分析する要求とゲームエンジンの対応範囲を不要に結び付けるため採りません。

新形式はイベントの重複を減らせますが、容量や速度の改善率は測定した範囲でのみ報告します。外部互換性の根拠は固定した参照実装と実入力のテストであり、全派生ツールとの適合宣言ではありません。
