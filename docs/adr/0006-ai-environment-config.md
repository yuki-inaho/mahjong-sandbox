# ADR-0006：AI設定、環境APIと評価を分離する

日付：2026-11-23。状態：採用。

## 背景

初版のGreedyは固定された判断規則で、探索予算や算法を設定できません。有効牌の残枚数を見ないため、残り0枚の待ちへリーチする例が再現しています。一方で、予算を増やしたという事実だけでは勝率が上がった根拠になりません。

利用者は後から木探索や強化学習を実装できる状態・行動・ログの入口と、TOMLによる設定を求めています。

## 決定

1. `Policy`は公開観測と合法手を受け取り、対局状態を書き換えません。Random、Greedy、Ukeireを別の算法として提供します。
2. プリセットは具体的な算法・乱数種・探索深さ・向聴計算回数の予算・防御重みへ解決します。解決済み設定を判断説明・評価・完全ログへ記録します。壁時計による打切りは判断の再現性を損なうため使いません。
3. TOMLとJSONは同じ設定型を使います。presetとalgorithmの同時指定は拒否します。明示的な予算等はプリセットの値を上書きし、最後に組合せを検査します。未知項目や未対応算法を既存算法へ置き換えません。
4. 研究用Environmentはreset/step/観測/合法手mask/報酬/終了を定義します。報酬は各席の持点差（点）で、リーチ供託の支払いを含みます。割引や独自の報酬整形は呼出し側の責務です。
5. 状態分岐を行う信頼する実験コードと、隠れた牌を見ないPolicyの権限を分けます。真の山を使った完全情報探索を、通常プレイヤーの強さとして評価しません。

## 行動番号

| 範囲 | 意味 |
|---|---|
| 0〜33 | 牌種IDの打牌 |
| 34〜67 | 牌種IDでのリーチ打牌 |
| 68、69、70、71、72、73 | ツモ、ロン、ポン、大明槓、見送り、次局 |
| 74〜107 | 牌種IDの暗槓 |
| 108〜188 | `108 + 順子の最小牌ID×3 + 鳴く牌の位置`で表すチー |

チーの順子開始は数牌の1〜7です。予約された無効番号は常にmask=falseです。同牌の複数のコピーは同じ行動IDを持ち、最初の合法な手牌indexへ正規化します。完全ログのWireActionは実際のindexを保持し、盤面が同じでも異なるindexを選んだ履歴を黙って書き換えません。

## 評価と限界

固定したseed・席・対照と、実効設定の識別を評価前に保存します。全試合を母数に残し、失敗・操作上限も報告します。開発用seedと評価用seedを分けます。プリセット名から勝率を推測せず、実測した比較の範囲で説明します。既学習モデルやRL訓練の成功は今回の成果に含めません。

参照した[mahjong-ai](https://github.com/clarkwkw/mahjong-ai)の複数算法と比較評価という構成を参考にします。香港麻雀向けのコードや学習モデルは流用しません。
